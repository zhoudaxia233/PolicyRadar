# Translation data

`content.json` maps the exact canonical explanatory text to its English translation.
The site offers Chinese and English only; German was removed as an interface language
on 2026-10-08. German original titles and documents are unaffected.
Chinese explanations remain in the source export. `lib/i18n/messages.ts` holds the
separate, type-checked interface dictionary. There is no runtime translation call.

`bindings.json` binds each policy to its source **version and SHA-256 hash**, and
each intake record to its hash. Hashes are generated by `contentHash` in
`lib/i18n/build.ts` over the parsed record returned by `createStaticData`, not over
raw JSON file bytes. Thus dates, citations and other fact-only edits also invalidate
translations. Intake hashes include the discovery timestamp added by that projection.
`originalLanguage` is the original document's BCP 47 language tag; it is not inferred
from the current locale or country. New data can set `originalLanguage` directly in
the policy or intake record. `verbatim` explicitly lists proper names and official
identifiers that were reviewed and should remain unchanged in both languages.
Do not use this list to exempt prose from translation. Intake bindings also record
`titleIsOriginal`: some legacy unverified records have Chinese editorial placeholders
in `title`, which must never be labelled as original titles.

To maintain translations after a data update:

Apply the [reader comprehension gate](../UPDATE.md#reader-comprehension-gate)
before binding a translation. Review Chinese and English independently
for understandable wording as well as factual equivalence. In particular, name
what every amount measures; do not translate an income ceiling as though it were
the amount a person pays. A fresh binding confirms coverage and record identity,
not comprehension. Record the editorial check in the update's review notes.

1. Read the changed canonical record and its evidence. Translate every explanatory
   field enumerated by `policyTextFields` (or the intake display title and note).
   Also translate new topic/status labels, review notes and scan notes. Preserve
   numbers, dates, exceptions, uncertainty and whether events are scheduled.
2. Retain official original titles, URLs, identifiers, tags, dates, evidence files
   and historical revisions. An English explanation of a source is an editorial
   explanation, not a replacement for its original text.
3. After reviewing the translations, use the candidate export's `createStaticData`
   result and `contentHash(record)` to update only the affected bindings. For
   policies, also copy `data.policyVersions[id]`. Never refresh all hashes just to
   make a stale translation appear current. Set the original language accurately.
4. Run the repository checks and build with the candidate export. Inspect
   `dist/data.json` → `localization.policies` / `localization.intake`. `current`
   means the translation covers the bound record; it does **not** assert legal
   accuracy. `missing` and `stale` show explicit fallback notices without hiding
   official discoveries. Keep historical text keys when adding replacements. The fixed export and
   `tests/fixtures/i18n-bindings.json` exercise the initial translated snapshot
   independently of later active-data updates; retain those regression fixtures.

Translations are presentation data. Do not rewrite historical exports or advance
factual verification dates just because wording was translated. Languages and
countries are separate dimensions; enabling a language never expands source coverage.
